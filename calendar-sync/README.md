# Googleカレンダー連携（毎日自動同期）

このアプリの実施・予約記録を、毎日自動でGoogleカレンダーの「いつものカレンダー」へ反映する仕組みです。

無料の「Google Apps Script」（Googleが提供する自動化ツール）を使います。追加のサーバーや有料サービスは不要です。

## できること

- 毎日決まった時刻（1日5回：6時・12時・15時・21時・0時）に自動でチェックし、実施済み・予約中の記録をGoogleカレンダーの予定として反映します
- 予定のタイトルは「会員名（実施済み）」または「会員名（予約）」の形式になります
- 会員の削除や、予約のキャンセル（記録の削除）があった場合、対応するカレンダーの予定も自動で削除されます
- 時間が設定されていない記録は、終日の予定として反映されます
- 過去14日分・未来60日分（設定で変更可能）が同期対象です
- （任意設定）アプリでGymsのCSVを取り込んだ直後にも、その場でカレンダーに反映できます

## セットアップ手順（初回のみ）

### 1. Supabase側の準備

まだの場合は、[`supabase/migration.sql`](../supabase/migration.sql) の内容をSupabaseのSQL Editorで実行してください（カレンダー連携用の列が追加されます）。

### 2. Google Apps Scriptのプロジェクトを作成する

1. **いつも使っているGoogleカレンダーと同じGoogleアカウント**で、ブラウザから https://script.google.com を開く
2. 「新しいプロジェクト」をクリック
3. 左上のプロジェクト名を「BUGカレンダー連携」など分かりやすい名前に変更する

### 3. コードを貼り付ける

1. エディタに最初から表示されている内容をすべて削除する
2. このフォルダの [`Code.gs`](./Code.gs) の中身をすべてコピーし、エディタに貼り付ける
3. 保存する（Ctrl+S / Cmd+S）

### 4. SupabaseのURLとキーを設定する

1. 左メニューの歯車アイコン「プロジェクトの設定」を開く
2. 「スクリプト プロパティ」で「スクリプト プロパティを追加」を押し、以下の2つを登録する

   | プロパティ | 値 |
   | --- | --- |
   | `SUPABASE_URL` | `supabase-config.js` に設定しているURL |
   | `SUPABASE_ANON_KEY` | `supabase-config.js` に設定している anon public キー |

3. 「スクリプト プロパティを保存」を押す

### 5. 自動実行を有効にする

1. エディタの画面に戻る
2. 上部の関数選択ドロップダウンから `setupTrigger` を選ぶ
3. 「実行」ボタンを押す
4. 初回は「承認が必要です」という画面が出るので、指示に従ってGoogleアカウントでの許可（**カレンダーへのアクセス**、外部サービスへの接続）を進める
   - 「このアプリは確認されていません」という警告が出ることがありますが、自分で作成したスクリプトなので「詳細」→「（プロジェクト名）に移動」で進んで問題ありません
5. 実行が成功すると、ログに「毎日朝5時ごろに自動実行するトリガーを設定しました。」と表示されます

### 6. 動作確認をする

1. 関数選択を `testRunNow` に変更して「実行」を押す
2. 「表示」→「ログ」で実行結果を確認する
3. ご自身のGoogleカレンダー（普段お使いのカレンダー）を開き、予定が反映されているか確認する

### 7. （任意）CSVアップロード時にその場で反映させる

1日5回の自動同期に加えて、アプリで「Gyms CSVで更新」を実行した直後にもすぐカレンダーへ反映したい場合は、以下の手順でこのスクリプトを「ウェブアプリ」として公開します。

1. エディタ右上の「**デプロイ**」ボタン→「**新しいデプロイ**」を押す
2. 「種類の選択」の歯車アイコンから「**ウェブアプリ**」を選ぶ
3. 「次のユーザーとして実行」は「**自分**」のまま
4. 「アクセスできるユーザー」は「**全員**」を選ぶ
5. 「デプロイ」を押す
6. 初回は承認画面が出るので、手順5と同じように許可を進める
7. 発行された「**ウェブアプリ**」のURL（`https://script.google.com/macros/s/....../exec` という形式）をコピーする
8. リポジトリ内の `supabase-config.js` を開き、`calendarSyncUrl` の欄にそのURLを貼り付けて保存する

   ```js
   calendarSyncUrl: 'https://script.google.com/macros/s/xxxxxxxx/exec',
   ```

   ※ このURLは他の人に知られると、勝手に同期を実行されてしまう可能性があります。`anonKey`と同様、公開リポジトリなどには注意してください。

これで、CSVアップロード完了時にアプリが自動でこのURLを呼び出し、その場でカレンダーに反映されるようになります（呼び出しに失敗しても、アプリ本体の動作には影響しません。1日5回の自動同期もそのまま動き続けます）。

**注意：** `Code.gs` の中身を後から変更した場合、「デプロイ」→「デプロイを管理」→編集（鉛筆アイコン）→バージョンを「新しいバージョン」にして「デプロイ」を押さないと、ウェブアプリ側には新しいコードが反映されません。

## 実行時刻を変えたい場合

現在は **6時・12時・15時・21時・0時** の1日5回、自動で更新されます。

回数や時刻を変えたい場合は、`Code.gs` の中の

```js
var SYNC_HOURS = [6, 12, 15, 21, 0];
```

の数字（0〜23の24時間表記）を書き換え、保存してから、もう一度 `setupTrigger` を実行してください（前のトリガーは自動的に削除され、新しい時刻に置き換わります）。

## うまく反映されない場合

- 実行ログ（「表示」→「ログ」）にエラーが出ていないか確認してください
- カレンダーへのアクセス許可を求める画面が出た場合は、必ず許可してください（許可しないとカレンダーに書き込めません）
- 会員名が正しく表示されない場合は、Supabaseの`members`テーブルと`session_logs`テーブルの紐付け（`member_id`）を確認してください
- CSVアップロード時にすぐ反映されない場合は、`supabase-config.js` の `calendarSyncUrl` が正しく設定されているか、`Code.gs` を変更した後に「新しいバージョン」でデプロイし直したかを確認してください（未設定でも1日5回の自動同期はそのまま動きます）
- ウェブアプリのURLを直接ブラウザで開いた時に「ERROR: 短時間に作成したカレンダーまたはカレンダーの予定の数が多すぎます。」と表示される場合は、Googleカレンダー側の一時的な制限です。アプリのバグではないので、少し時間（30分〜1時間程度）を置いてからもう一度お試しください。短時間に何度も手動でテスト実行を繰り返すと発生しやすくなります
